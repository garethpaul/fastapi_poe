# OpenAPI Generator Deep-Review Design

## Context

PRs #2 and #3 both add a script that serializes `make_app(...).openapi()` directly. The current FastAPI route is intentionally implemented with a raw `Request`, so its generated schema omits the Poe protocol request body and response media types. One draft also constructs an unauthenticated app while FastAPI still advertises bearer authentication; the other combines an explicit key with `allow_without_key=True`, which does not disable authentication. Both scripts therefore publish a plausible-looking but materially incomplete contract.

## Approaches Considered

1. **Serialize FastAPI's raw schema unchanged.** Smallest patch, but it preserves missing request schemas, generic operation IDs, JSON-only responses, and ambiguous authentication. Rejected.
2. **Change the production route signature to use a discriminated Pydantic union.** This would improve `app.openapi()` globally, but it also changes request parsing and error behavior in a mature runtime path. The PRs are documentation tooling, so that blast radius is not justified here.
3. **Build and validate a public documentation schema from a local fixture.** Use the real `make_app` route as the source of paths/security, then normalize the known protocol boundary from the exported request and response models. This keeps the runtime untouched while making drift and omissions fail closed. Chosen.

## Architecture

`docs/generate_openapi_spec.py` creates a local authenticated Poe bot with documentation routes disabled and no bot name, so generation performs no provider calls or settings synchronization. The generator retains only the configured public bot path, assigns stable operation IDs, describes HTML, SSE, and JSON responses, and creates a discriminated request union from the package's five protocol request models. Internal `access_key` and deprecated `api_key` fields are removed from the public query request schema.

A validator enforces the public path/method allowlist, bearer security, unique operation IDs, exact request variants, response media types, component references, and bounded route/component/document sizes. JSON and Markdown serialization are sorted and deterministic. The CLI accepts explicit output paths, rejects symlinks and non-regular targets, limits generated bytes, and atomically replaces files with private temporary files and directory `fsync` where supported. Expected errors are concise; unexpected exceptions are not echoed, preventing accidental secret disclosure.

## Verification

Unit tests use local FastAPI fixtures only. They cover hidden-route filtering, schema fidelity, bearer accuracy, operation IDs, deterministic output, endpoint overview content, path/type/symlink rejection, atomic replacement, size bounds, and redacted CLI failures. Hostile mutation tests remove or alter required schema invariants and require the validator to reject every mutation. Existing lint, type, and multi-version test gates remain authoritative; CI receives explicit read-only token permissions and non-persistent checkout credentials.
